## 1. Objetivo práctico

Realizar una auditoría heurística sobre una interfaz separada del proyecto incremental principal, documentando hallazgos por cada heurística relevante.

---

## 2. Contexto de la práctica

Este módulo no continúa técnicamente el proyecto 01-11. Se trabaja como un track aparte, enfocado en análisis UX. La meta es observar y diagnosticar antes de rediseñar.

---

## 3. Archivos que se van a modificar

- documento de evaluación heurística
- capturas en `assets/`
- notas del caso analizado

---

## 4. Archivos base desde `files`

La carpeta `files` puede usarse para plantillas de checklist o fichas de observación del ejercicio.

---

## 5. Código o material inicial

Usar [angular/docs/A-heuristicas.md](../docs/A-heuristicas.md) como marco conceptual de referencia para la evaluación.

---

## 6. Pasos incrementales

### Paso 1. Seleccionar la interfaz a evaluar

Puede ser una interfaz propia o una interfaz propuesta en clase.

### Paso 2. Definir tareas de usuario

Especificar qué acciones intentará realizar el usuario en la interfaz analizada.

### Paso 3. Revisar heurísticas clave

Aplicar al menos visibilidad del sistema, consistencia, prevención de errores y recuperación de errores.

### Paso 4. Documentar evidencia

Agregar capturas y describir claramente el problema detectado.

### Paso 5. Priorizar hallazgos

Separar problemas críticos, moderados y menores.

---

## 7. Validaciones esperadas

- La evaluación no se limita a opinión general.
- Cada hallazgo se vincula con una heurística.
- Existen evidencias visuales del problema.
